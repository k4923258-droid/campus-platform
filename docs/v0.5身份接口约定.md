# v0.5 身份接口约定（本地实现）

本文件记录当前本地实现的接口；线上尚未部署。学校认证预留，学校端协议与参数待校方资料确认。

## POST /api/v1/auth/email/challenges

输入邮箱和用途（register/password-reset），返回申请标识、有效期及下次可申请时间；验证码只发送到目标邮箱，不在接口响应中返回。按账号存在与否使用统一恢复响应；发送失败或触发限制时给出不暴露账号详情的可修正提示。

## POST /api/v1/auth/register

输入注册申请标识、验证码、平台密码和显示姓名；后端从申请记录确认邮箱和可信映射学号，不接受前端自行指定权限。成功创建普通账号；映射未就绪、过期或冲突时不激活正式业务权限。

## POST /api/v1/auth/password/reset

输入恢复申请标识、验证码和新密码；校验后更新密码、一次性消费凭据并撤销该账号全部既有会话。不得复用注册申请或替换申请所绑定邮箱。

## GET /api/v1/auth/providers

返回平台密码、校邮核验及学校认证等方式的可用状态和本站入口，不返回密钥；学校未接入时返回不可用，模拟来源必须明确区分。

## GET /api/v1/auth/login/neu

学校认证登录发起接口，当前预留；就绪后仅允许配置的认证中心及本站返回路径，保存请求关联信息，不接收学校密码。

## GET /api/v1/auth/callback/neu

当前预留；协议确定后按校方约定接收并由后端校验凭据，再映射用户；不能仅因URL含ticket、code或学号就认定成功。方法、参数及安全要求如与校方协议不同须登记接口变更。

## GET /api/v1/session

查询是否登录、当前公开用户信息、身份来源及邮箱/学号/账号状态；不返回密码哈希或有效认证凭据。

## POST /api/v1/session

平台密码登录，沿用学号或既有账号入口；正确密码不能越过待验证、身份冲突或停用限制；演示账号只能在隔离模式按演示规则使用。

## DELETE /api/v1/session

退出并使当前平台会话失效，遵循现有CSRF保护；本版不承诺学校全局单点退出。

正式模式不得保留旧 /api/v1/commands/register 免验证入口；邮箱映射待确认时不激活报名权限。业务通知仍使用站内信，身份和恢复邮件为例外。

## 补充接口与当前边界

- `POST /auth/identity/bind`：待核验账号补充可信绑定，需当前密码与bind用途验证码。
- `POST /auth/email/change`：已核验账号换绑，需当前密码、email-change用途验证码；原地址收到安全通知。
- `POST /activities/{activityId}/team-members/resolve`：已核验用户按完整学号查询可加入账号，最小字段返回。
- `GET /auth/identity-conflicts` 与 `POST /auth/identity-conflicts/{id}/resolve`：管理员核验冲突、选择报名迁移范围，不继承旧管理权限。

以上路径均以`/api/v1`开头；状态码、字段与CSRF约定见`openapi.json`。正式、local-mail与demo身份分别隔离。新域名映射未启用；学校认证两个入口固定返回503，不接收学校密码，也不根据客户端ticket/code创建会话。
