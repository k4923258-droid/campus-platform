# 五人协作与模型任务单

| 成员 | 负责成果                             | 复核人 |
| ---- | ------------------------------------ | ------ |
| A    | 需求追踪、业务规则、用例与验收记录   | D      |
| B    | 交互流程、动态表单、移动端与键盘操作 | C      |
| C    | 公开页面、学生中心、团队报名         | B      |
| D    | 活动配置、审核、面试、录取           | A      |
| E    | 接口契约、Java与数据库、集成及运维   | D      |

后端按业务由各负责人配合维护，E统一接口与集成。模型输出必须由负责人运行核验后交给复核人，不能把AI的自述当成测试结果。

## 每次交给模型的输入

```text
需求编号：
本次只处理的页面或操作：
角色与所属组织：
相关文件及接口契约：
前置状态、输入与预期状态：
必须通过的正常与失败场景：
不允许改变的既有规则：
交付：代码修改、运行命令、实际检查结果、未解决事项。
```

推荐任务颗粒：一个字段类型、一个审核操作、一个页面错误状态或一组针对性测试。修改公共类型、接口或数据库迁移时先更新契约，再修改调用方。模型API仅输入模拟数据；密钥放本地环境变量，禁止打包到前端或提交仓库。

用量记录：日期、模型、任务编号、输入/输出Token、费用、任务负责人、复核结果。不预设未经确认的价格；调用前由E核对计费与提醒设置。
